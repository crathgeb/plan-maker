How plan-maker fits together

Claude writes a plan as an HTML page. You mark it up and work through it in the browser, and a small local server saves everything to notes.json. Claude reads that file to write the next version. Every step in a plan has an owner: You or Claude. The registry and the hub keep every plan, across all your projects, in one place.

The pieces

On the left, one project's plan and its review server. On the right, the registry that knows about every project and the hub that shows it. Claude keeps both in step.

  1. 1Skills and plans. make-plan writes the page. process-plan-notes reads notes.json, saves the current version with snapshot.mjs, then writes vN+1.
  2. 2Skills and the registry. registry.mjs add for a new plan; update --log for each version or status change.
  3. 3Review server and plan. It reads the plan fresh on every load and writes notes.json as you type.
  4. 4You and the review server. Nothing leaves your machine unless you start it with --host.
  5. 5Hub and registry. The hub lists every plan; changing a status writes it back, with a log line.
  6. 6Live progress. Each owner's steps done, open decisions, unprocessed notes and what's waiting on you are read from the plan and its notes when you look.
  7. 7Open starts a review server, or reuses the one already running, and takes you to the plan.
  8. 8You and the hub. Projects in the sidebar, plans beneath, waiting on you first. It refreshes itself.

A plan's life

Who acts at each point, and what lands in the registry.

ClaudeWrites v1Researches, writes the plan with every step owned by you or Claude, starts the review server.add · reviewing
YouReview itComments and questions, decisions, drawings. Then Done for now.hub: tell Claude “process my notes”
ClaudeWrites v2Saves v1 with your notes, applies them, answers your questions where you asked them, adds “What changed”.update --log "v2: …"
YouApprove itWhen no decisions are left open.status → approved
YouDo your stepsTick each one off with Mark done. Ask about anything that's unclear.hub: 2 of your steps left: …
ClaudeDoes its stepsSets each step's status to in progress, then done. Your ticked steps carry into every new version.in-progress → done

Review and revise repeat as often as you like, and every version stays in the switcher. A walkthrough is the same thing with mostly your steps. If you're stuck on someone else, Claude sets blocked and writes what you're waiting on as the next action.

Statuses

Every status except done and archived counts as active.

draft→ reviewing→ approved→ in-progress→ done any time: blocked archived

The same, without Claude

# one plan
node scripts/review.mjs plans/docs/index.html      # review it in the browser
node scripts/snapshot.mjs plans/docs/index.html    # save vN before revising
node scripts/bundle.mjs plans/docs/index.html      # a self-contained copy to share

# every plan
node scripts/registry.mjs scan                     # register every plan-maker page in this project
node scripts/registry.mjs update plans/docs --status in-progress --log "Phase 1 done"
node scripts/registry.mjs list [--all] [--json]
node scripts/hub.mjs                               # the hub, at http://127.0.0.1:4477/
