Move the docs site to a static generator

Plan v1For review9 Nov 2026

Replace the hand-maintained docs pages with a static site built from the Markdown already in the repo, so docs ship with the code that they describe.

Based on the current docs folder, last quarter's support tickets and the build pipeline.

Information

What you need to know: why, what gets built and what could go wrong. Nothing here is a step.

The short version

Docs drift because they live apart from the code. Generating them from the repo fixes that and cuts publishing from a day to a merge.

Goal

Docs ship with the code

Every merged change can update its docs in the same pull request.

Scope

Guides and reference

About 60 pages. The blog and changelog stay where they are.

Effort

About three weeks

Claude does the conversion; you review the migrated pages in week two and switch the domain over in week three.

Not in this plan: a redesign. The new site copies today's look; design changes come after.

How it works

What the finished docs site does: the design, not the work. The phases build it, starting with Scaffold and import.

  • One source. Pages are Markdown files in docs/, next to the code.
  • Preview on every pull request. Reviewers see the rendered page before merging.
  • Every old URL keeps working. A redirect map is generated from the old sitemap.
docs/
  guides/        how-to pages
  reference/     generated from the API schema
  redirects.json old URL → new URL

Steps

The work, in order. Yours are blue, Claude’s are gold.

Phases

The work, in order: four phases over three weeks, yours in blue and Claude’s in gold. Your part in the switch-over has its own guide.

Scaffold and import

Week 1

Set up the generator with preview deploys, then convert every existing page and list what the converter couldn't handle.

Done when all 60 pages build, and every pull request gets a preview link.

  • Set up the generator and preview deploys
  • Convert the 60 pages
  • Fix by hand what the converter missed

Review the migrated pages

Week 2 · about 2 hours

Read every page on the preview site and comment on this plan wherever something looks wrong.

Done when you've read every page and nothing you flagged is still open.

Switch the domain over

Week 3 · about 30 minutes

Claude prepares the DNS records and the redirect map; you add them at your registrar and check the site.

Done when docs.example.com serves the new site and old links redirect.

Retire the CMS

A month after the switch

Keep the CMS read-only for a month in case anything was missed, then shut it down.
