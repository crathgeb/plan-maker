Plan v1 · for review · 7 Nov 2026

Move the docs site to a static generator

Replace the hand-maintained docs pages with a static site built from the Markdown already in the repo, so docs ship with the code that they describe.

How to review: select any text and click Add note · mark each card or row Keep / Change / Cut · answer the decisions at the end · press Done reviewing, then tell Claude “process my notes”.
Based on: the current docs folder, last quarter's support tickets, the build pipeline.
1 · Summary

The short version

Docs drift because they live apart from the code. Generating them from the repo fixes that and cuts publishing from a day to a merge.

Goal

Docs ship with the code

Every merged change can update its docs in the same pull request.

Scope

Guides and reference

About 60 pages. The blog and changelog stay where they are.

Effort

About three weeks

One engineer, with a writer reviewing the migrated pages in week two.

Not in this plan: a redesign. The new site copies today's look; design changes come after.

3 · Approach

How it works

  • One source. Pages are Markdown files in docs/, next to the code.
  • Preview on every pull request. Reviewers see the rendered page before merging.
  • Every old URL keeps working. A redirect map is generated from the old sitemap.
docs/
  guides/        how-to pages
  reference/     generated from the API schema
  redirects.json old URL → new URL
4 · Phases

Rollout

1

Scaffold and import

Week 1
  • Set up the generator and the preview deploys.
  • Convert the existing pages with a script; fix by hand what it misses.
2

Review and redirect

Week 2
  • The writer reviews every page.
  • Generate and test the redirect map.
3

Switch over

Week 3
  • Point the domain at the new site; keep the CMS read-only for a month.
